# BiliMusic · Vela 手表端

小米 Vela JS 快应用形态的 BiliMusic 播放器。登录后即可播放自己的收藏夹与官方推荐曲目。

> BiliMusic 主仓库为 Flutter 端（Windows / Linux / Android / macOS / iOS / Web），本目录 `vela/` 是与之并列的 JS 快应用实现，**不与 Flutter 端共享代码或依赖**。
> 本仓库与所有派生作品遵循 AGPL-3.0，仅供学习交流，不得商用。

## 安装

构建产物为 `.rpk` 包。

```bash
npm install            # 首次：安装 AIoT 工具链
npm run build          # 在 build/ 下生成 RPK
npm run release        # 构建并生成发布包（需要签名）
```

把 RPK 装到设备有五种途径：

- [**AstroBox**](https://astrobox.online/)：推荐，第三方完善的穿戴工具箱。
- [**表盘自定义工具**](https://www.bandbbs.cn/threads/9797/)：老牌米坛社区穿戴设备工具箱。
- **旧版小米运动健康**：【我的】-->【关于】-->【Debug】-->【第三方应用】安装
- **AIoT IDE 调试安装**：`npm run start` 启动调试模式，按官方文档推送 RPK 到手表 / 模拟器。
- **本地调试服务器**：`aiot server --watch` 后在设备上扫描二维码即可安装并热更新（仅限开发期）。

> **NOTE**：修改 `manifest.json`（后台运行声明、能力列表）后必须重新 `npm run build` 重装 RPK，热更新不会替换已安装包的声明。

### 版本号由 CI 对齐，不用手改

`src/manifest.json` 里的 `versionName` / `versionCode` **不要当成手工发布项**：仓库的 Release CI（`.github/workflows/release_build.yml` 的 `build_vela` job）出包前会强制改写它们，改写规则与 Flutter 端同源：

| 字段 | CI 取值 | 含义 |
| --- | --- | --- |
| `versionName` | pubspec.yaml 的主版本号（`MAIN_VERSION`，如 `1.9.1`，不含 `+build`） | 与 Flutter 端 versionName 严格一致 |
| `versionCode` | `git rev-list --count HEAD`（提交数 `BUILD_VERSION`，如 `170`） | 与 Flutter 端 build number 同源，随每次提交单调递增 |

所以本地 `manifest.json` 里的这两个值是「上次手改留下的快照」，会在漂移后被 CI 覆盖：

- 覆盖发生在 `npm run verify` **之前**、`npm run release` **之前**，因此 RPK 包内元信息与产物名（`bilimusic_vela-<versionName>-<versionCode>.rpk`）一定是本次构建对齐后的值。
- CI 会校验 `versionName` 形如 `x.y.z`、`versionCode` 为正整数，并把改写成 JSON number；拿不到合法值时直接 fail，不会打出一个版本号残缺的包。
- 本地开发用 `npm run build` / `npm run release` 时**不会**自动对齐（CI 才有 `BUILD_VERSION`），此时包内版本就是 `manifest.json` 的当前值，属预期行为。

## 第一次打开

应用入口是播放页。首次启动时点击右上角「更多」入口即可看到登录入口。

## 登录

B 站账号必须登录后才能使用收藏夹功能。推荐流和热门无需登录。

1. 在「更多」页点击「去登录」（或直接访问收藏夹触发的登录拦截）；
2. 登录页会展示一个二维码（TV 端扫码登录）；
3. 打开手机哔哩哔哩客户端 → 我的 → 扫一扫，扫描二维码；
4. 在手机上点击确认登录；
5. 登录页底部点「返回」回到上一页（不会跳转到更多页）。

登录态与用户资料会保存到本地，下次启动自动恢复。Cookie 有效期约半年，过期后重新扫码即可。

> **TIP**：二维码失效或加载失败时，直接点击二维码区域即可重新获取。

## 主要功能

### 自适应

使用了 `@system.device` 查询设备信息，同一个应用适配方屏和圆屏。

### 推荐（更多 → 官方推荐）

无需登录即可访问的官方推荐流。当推荐流接口不可用时会自动回退到热门榜。

### 收藏夹

登录后可访问自建的全部收藏夹。每个收藏夹按曲目分页展示，可单曲点播或「播放全部」连播整个收藏夹。

### 播放

- **单曲点播**：在收藏夹 / 推荐页点某首曲目，立即播放。已存在于播放队列时会跳播到该曲目；不存在时插入到当前曲目之后，队列原有内容保留。
- **播放全部**：按列表顺序从第一首连播整个来源（收藏夹或推荐）。
- **连续挑歌**：可跨来源（收藏夹、推荐）连续点播多首，按点播顺序排在当前曲目之后。

### 播放队列

播放页向左滑动进入第 2 屏即播放队列：

- **移除曲目**：点击条目右侧 × 即可移除。正在播放的曲目被移除时自动接播下一首（队列末尾则回到队列首）。
- **正在播放的曲目**：用 `♪` 标记，标题使用跑马灯防止截断。
- **跳播**：点击队列中任意曲目即切歌。
- **返回**：点击顶部「‹ 播放队列」或向右滑回第 1 屏播放器。

> **关于表冠**：表冠旋转 = 当前屏内容滚动。第 2 屏旋转表冠即滚队列；第 1 屏旋转无动作（横向翻页必须用手指或顶部返回），这是横向翻页交互的已知取舍。

> **关于耗电**：播放进度由原生事件驱动（`ontimeupdate` 4Hz + 每秒一次对账）。播放页切到其它页面时页面并不销毁，原生事件仍绑在播放页的 VM 上，所以离开播放页时除了停掉对账定时器，还会把「不可见」这一状态交给 `playerService`，由它挡掉进度的广播 —— 不可见期间不再每秒重算约 5 次界面数据。进度镜像照常刷新，回到播放页立即是最新值，不会出现「回来要等一秒才动」。

### 播放页

第 1 屏包含：

- **封面背景图**：当前曲目封面，部分机型无法渲染时自动回退为纯黑底。
- **歌名 / 歌手**：播放态文案优先于歌手行（暂停时显示「已暂停」等提示）。
- **进度环**：显示播放进度。
- **控制条**：上一首 / 暂停-继续 / 下一首。
- **音量按钮**：进入音量调整页。

### 音量

本应用的音量**直接读取与写入系统媒体音量**，不维护独立的音量记忆。好处是与系统设置、实体音量键完全同步；代价是重装应用、清数据均不会改变音量。

进入「音量」页后：

- 屏幕中央的音量条显示当前系统音量；
- 上下调节通过 `+` / `−` 按钮（步进规则：临近 0/100 时自动吸附）；
- 贴底的圆形按钮关闭音量页返回播放页。

> **老机型降级**：若设备完全不支持系统音量接口，应用会降级为播放器内置音量并保持音量页可用，但此时与系统音量不再联动。

## 音频缓存

应用会自动缓存已播放过的音频文件，下次播放同一首直接秒开不再消耗网络。

- **保留策略**：常驻 3 首（当前曲目 + 前后曲目），其余自动清理。
- **查看与清理**：更多 → 清理音频缓存，显示当前占用与歌曲数，可一键清空。
- **网桥机型**：由于蓝牙带宽限制，首次播放一首新歌需要等待落盘（几秒到几十秒），之后秒开。
- **原生机型**：仅当直链播放失败时才落盘缓存，正常情况下听歌不产生缓存。

> 应用启动时会自动清理上次运行意外留下的半成品缓存文件，不会影响完整缓存。

## 网桥模式

Redmi Watch 4 系列、Xiaomi Watch H1 E 等机型没有独立网络，需要借助手机端联网：

1. 在手机上安装 [AstroBox](https://astrobox.online/) 工具箱，连接你的手表；
2. 安装「网桥 FetchBridge」插件（`.abp`）；
3. 在插件页面中给本应用（包名见关于页）开启「监听」；
4. 手表端会自动通过手机端联网，无需额外设置。

日志中出现 `provider=bridge` 即表示正在走网桥通道。握手失败时检查 AstroBox 中是否给本应用开启了「监听」。

## 已知限制

- **不支持手环**：机身无扬声器，无法出声。
- **不支持创建 / 修改收藏夹**：只能读取已有的收藏夹。
- **不支持播放进度拖动**：当前不提供拖动 UI（功能已就绪，未做界面）。
- **不支持排序**：队列按点播顺序与连播顺序排列，无手动排序。
- **不支持续期 Cookie**：Cookie 过期后需重新扫码。

## 常见问题

**Q：扫码登录提示「Cookie 信息不完整」。**
A：当前仅支持 TV 端扫码登录一条路径，请确保用手机哔哩哔哩客户端最新版扫描。

**Q：登录成功了但收藏夹页面提示「访问权限不足」。**
A：进入「更多」页确认是否已正确登录；若仍提示请退出登录后重新扫码。

**Q：播放歌曲时没反应。**
A：检查通知栏是否显示图标。若没有，请确认应用版本与系统音量。

**Q：返回表盘后音乐自动停止。**
A：本应用依赖系统后台运行机制，很可能是你的机型因为省电策略强制停止了应用。

**Q：网桥机型显示「握手超时」。**
A：检查手机端 AstroBox 是否给本应用开启了「监听」；确认手机与手表蓝牙连接正常。
